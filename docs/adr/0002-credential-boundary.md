# ADR 0002：凭据边界与 FR-007 范围

日期：2026-09-20。状态：初始决策；上游事实按「待 T001 复核」处理。

## 背景

001 规格 FR-007 要求「凭据只保存系统凭据引用」，CONTEXT 不变量也写作「凭据由 OS 凭据存储引用」。但受管 DSH 的真实行为显示：DSH 首次 `web` 启动会在环境 home 自动生成 `.credentials.yaml`（权限 0600，含 Web 会话 grant secret），并写 `logs/` 启动诊断。该文件是凭据类秘密，但不是由 HDSL 的 OS 凭据存储引用保存的，而是上游落盘产物。继续用单一不变量描述，会让规范层与实现/验收互相矛盾。

证据来源：PR #14 的探针脚本与记录（`docs/research/dsh-behavior-probes.md`，固定 commit `c092f67b25f7233bd49e0c1452bdd0df2cd3516a`，对应 S2 与「其他观察 2」）。该证据**尚未合并进 main**，且 T001（issue #1）的交付物是 `docs/research/dsh-compatibility.md`（当前不存在）。因此在 T001 复核转正前，本 ADR 把该行为标注为「待复核」，不写死为所有版本的必然行为，也不据此声称已支持。

## 决策

把凭据分为两类，分别约束：

1. **受管用户凭据**（如模型 API key）：HDSL MUST 只保存 OS 凭据存储（keychain/credential manager）引用，启动时按引用解析并注入显式进程环境；值不写入环境目录、操作日志、诊断导出、整合包或 Git。
2. **上游生成的本地凭据产物**（如环境 home 的 `.credentials.yaml` Web grant secret 及相关日志）：HDSL MUST 把环境 home 整体视为含密数据；这些产物不要求由 OS 凭据存储引用，但 MUST 排除出整合包、诊断导出、普通日志与 Git，不跨环境复制，导出前脱敏。

两类共同底线：任何秘密不进入整合包、诊断导出、普通日志与 Git。

## 替代方案

- **B：维持单一「凭据只存系统凭据引用」不变量**，要求 HDSL 把上游 `.credentials.yaml` 改由 OS store 管理或等价隔离。当前无证据支持可干净替换上游写入行为，且易与上游升级冲突，不采用。
- **C：不区分，笼统承诺上游不落盘凭据文件**。与已观察行为矛盾，也无法验收，不采用。

## 后果

- FR-007 与 CONTEXT 不变量改为分栏表述；T005/T006/T007 的验收分别覆盖两类。
- 环境 home 的导出/打包/日志路径必须有明确排除与脱敏规则；后续 003 整合包规格继承该边界。
- T001 在 `docs/research/dsh-compatibility.md` 复核文件名、路径、权限与版本范围后：
  - 若与假设一致，将本 ADR 与相关规范中的「待复核」改为已核实；
  - 若不一致，修订本 ADR 与相关规范，不静默放宽秘密保护。
