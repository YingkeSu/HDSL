# HDSL 概览

可以把 HDSL 理解为“面向 AI 工作环境的版本管理员”。Minecraft 启动器将游戏、Java、Mod 组合起来；HDSL 计划将 Node、DSH、插件及配置组合起来。共同难点是组件版本不同步和升级失败，额外难点是 AI 工具能修改工作目录或调用外部服务。

用户首先创建“论文阅读”或“代码实验”环境。每个环境锁定一组运行时和插件。点击启动后，HDSL 用指定运行时和环境设置启动 DSH。升级时先展示变更，在旁边准备新代际，验证成功才启用。遇到问题可切回旧代际。

“代际”类似保存的一套工具箱，而不是整个世界的时间机器。切回旧工具箱不会撤回已发送的消息，也不会自动恢复被插件修改的论文文件。新代际产生的会话也不会自动合并回旧代际，因此界面必须说明数据边界。

整合包类似一张经过校验的配方：列出精确版本、下载来源、文件摘要以及可公开的配置。导入时先检查兼容性并显示变化；用户仍需提供自己的密钥。配方必须描述清楚，但插件是否可信仍需要来源和能力说明。

开发顺序为：验证 DSH 的真实接口 → 一个隔离环境能启动 → 插件事务与恢复 → 整合包 → 社区 → 小程序。前四步先解决本地实际需求，后两步验证分享和发现的价值。

项目已实现本地环境创建、安装与启停。上文中的插件事务、代际升级恢复和整合包仍是设计目标；当前能力见[项目 README](../../README.md)，验证范围见[路线图](../development/roadmap.md)。
