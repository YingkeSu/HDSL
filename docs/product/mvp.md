# MVP：先完成本地环境闭环

## 目标

面向同时使用多组 DSH/插件组合的个人用户，让其无须手工切换全局安装即可创建、启动、升级、恢复和分享环境。

## 纳入首版

1. 环境列表与单一主启动操作，展开后查看版本、插件、状态及错误。
2. 受管 Node/DSH 精确版本安装、摘要校验、缓存复用与独立环境设置。
3. 环境启动、停止、状态与脱敏日志；拒绝不受支持的组合。
4. 插件添加、删除、精确锁定及兼容性检查；变更预览 → 新代际 → 验证 → 切换。
5. 整合包导出、预检、导入新环境；缺少凭据时提示补充。
6. 安装失败、中断和升级失败恢复；清楚解释运行数据的恢复边界。

## 首版排除

独立论坛、在线 Registry、微信小程序、远程命令执行、OS 级插件沙箱、全量自动兼容性推断、旧会话自动合并、移动端启动 DSH。

## 发布门槛（待实施验证）

- 在明确记录的 macOS ARM64 与 Windows x64 实机上各完成安装、启动、插件变更、导入导出、恢复流程；Linux 是后续支持候选。
- 两环境使用不同精确版本，无配置、插件、凭据引用或会话目录串用。
- 安装每个提交阶段注入失败后，重启可解释状态且仍有可启动旧代际。
- 5 名目标用户中至少 4 名在不借助终端的情况下完成准备好网络及凭据后的创建与启动；记录失败原因而非只记成功率。
- 高风险验收场景全部有证据，无已知凭据泄漏或目录穿越问题。

## 前置验证

必须先固定上游仓库/提交、安装来源、Node 要求、profile/home 参数、插件与 bundle 命令、启动就绪信号和授权条件。若 DSH 无法隔离某类状态，先缩小支持范围并更新规格。
