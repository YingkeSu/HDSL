# 任务交接

## 任务契约（派发时必须填全）

- 任务/Issue：
- 基线 commit / 分支：
- 目标与不在范围：
- 文件/模块所有权：
- 依赖与接口版本：
- 验收（可机械判定）：
- 已完成变更：
- 实际运行的检查、结果与证据：
- 未验证项/阻塞/下一步：
- 停止条件：交付物完成且所需检查通过后报告并停止；无 checks 时明确报告，不无限等待。

## 阶段状态（每次更新必填）

- 阶段：<待开始 / 进行中 / 等待独立复审 / 已 push / 阻塞 / 已完成>
- updatedAt：<ISO8601 UTC>
- 当前 head：<sha>
- 已审 head：<sha 或 none>
- checks：<命令 + 结果；无 checks 写“无检查”>
- 下一步：

规则：`已审 head` 与 `当前 head` 不一致时旧审核结论失效，必须重新审核；延迟回执按 issue + PR + SHA + 阶段 + 时间去重。详见[编排 SOP](orchestration-sop.md)。

- 经验沉淀：领域术语写 CONTEXT；架构决策写 ADR；可重复操作写开发文档。

你不是唯一贡献者：不得回退他人的改动；发现接口冲突先同步，调整自己的实现。
