# 工程原则

## 用户结果

优先交付简洁启动、独立环境、插件和整合包闭环。每个功能有可独立验收的用户场景；社区功能在本地闭环后考虑。

## 精确组成与边界

受管运行时及插件锁定精确版本、来源和摘要。组成不可变不代表运行数据不可变；目录隔离不等于操作系统沙箱。

## 失败可恢复

环境变更通过独占锁、持久化 journal、新代际验证与活动指针提交协调。未验证成功不得破坏旧代际，运行中拒绝组成变更。向用户明确恢复涉及哪些数据。

## 窄接口与最小权限

领域核心不依赖 UI；renderer 不直接调用系统能力；DSH 内容不暴露启动器 IPC。凭据不进入版本库、日志或整合包，上游真实接口通过独立适配层核验。

## 风险驱动验证

核心需求和高风险故障需要验收证据；使用真实文件、进程与实机测试验证关键边界。未验证的平台不标为支持，测试替身不作为真实运行证据。

原则变化通过 [ADR](../adr/README.md) 记录原因、影响与迁移方式。上述原则约束设计，不表示后续插件、升级或整合包功能已经实现。
