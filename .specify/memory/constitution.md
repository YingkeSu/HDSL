# HDSL Constitution

## Core Principles

### I. 用户结果优先

优先交付简洁启动、环境隔离、插件和整合包闭环。每个功能有可独立验收的用户场景；论坛和小程序延后。

### II. 精确组成与显式边界

受管运行时及插件锁定精确版本、来源和摘要。组成不可变不代表运行数据不可变；目录隔离不宣称安全沙箱。

### III. 失败可恢复

环境变更具有独占锁、持久化 journal、新代际验证和活动指针提交。未验证成功不得破坏旧代际；运行中拒绝变更。恢复范围必须呈现给用户。

### IV. 窄接口与最小权限

领域核心不依赖 UI；renderer 不直连系统能力；DSH 内容不暴露 launcher IPC。凭据不进入版本库、日志或整合包。上游真实接口通过独立适配层核验。

### V. 风险驱动的验证

P0 需求和高风险故障有验收证据，不追求无差别 100% 行覆盖。真实进程/文件测试验证关键边界；实机未验证不得标记为支持。

## Engineering Constraints

初始选型 Electron + React + TypeScript、独立受管 Node/DSH。实际依赖版本和兼容矩阵以研究证据决定。上游代码复用先记录来源与许可。

## Workflow

需求 → spec → plan/契约 → tasks → 实现 → 检查/评审。新证据改变范围时更新相应文档。多 agent 明确任务与文件所有权，不覆盖他人工作；等待指令必须有可满足终止条件，无 checks 时报告后停止。

## Governance

用户明确决策优先。原则变更通过 ADR 说明影响与迁移；原则大改升 major，新增原则升 minor，文字澄清升 patch。实现与验证状态必须如实记录。
